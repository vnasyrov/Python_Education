# Шпаргалка: PageObject

## 1. Что такое PageObject
Класс-«стена с выключателями» для одной страницы.
- Внутри: селекторы и последовательность действий («как кликать»).
- Снаружи: методы с бизнес-именами + данные («что делаем»).

```python
registration_page.fill_birthday(12, 'July', 1993)   # тест говорит ЧТО
# а КАК (клики по календарю) спрятано внутри метода
```

## 2. Структура проекта
```
project/

│   └── registration_page.py      ← класс страницы
├── tests/
│   ├── test_demoqa_form.py       ← ДО: тест без PageObject (для сравнения)
│   └── test_with_page_objects.py ← ПОСЛЕ: тест через RegistrationPage
├── utils.py                      ← close_modal, path

```
- модуль = файл `.py`, пакет = папка с модулями
- точка в импорте = «внутри»: `from pages.registration_page import RegistrationPage`
- `base_url` = только сайт (`https://demoqa.com`), путь страницы живёт в `open()`
- открой оба теста рядом: ~70 строк селекторов vs ~25 строк, которые читаются как анкета

## 3. Ловушка «кофемашина»
Метод принимает параметр, но внутри его не использует:
```python
def fill_gender(self, value):
    ...have.exact_text('Male')...   # ❌ value выброшен
    ...have.exact_text(value)...    # ✅
```
Тест зелёный **случайно**, потому что передали то же, что зашито внутри.
Самопроверка: передай другое значение (`'Other'`) и посмотри, что изменится.

## 4. Звёздочка *
```python
def f(*values):       # в def СОБИРАЕТ:      f('a', 'b') → values = ('a', 'b')
    ...
f(*values)            # при вызове РАСКЛАДЫВАЕТ: ('a', 'b') → f('a', 'b')
```
Пример: `have.exact_texts(*values)`, потому что `exact_texts` ждёт тексты по одному, а не кортеж.

## 5. Один элемент или много
| Ситуация | Инструмент |
|---|---|
| элемент один | `browser.element(sel)` |
| похожих много, нужен один | `browser.all(sel).element_by(have.exact_text(value))` |
| проверить всю группу | `browser.all(sel).should(have.exact_texts(...))` |

`element()` берёт **первый** подходящий, это источник тихих ошибок.
У коллекции нет `.click()`: сначала выбери один элемент.

## 6. Селекторы и форматирование
- `#id`, `.class`
- пробел = «внутри»: `#genterWrapper label`
- без пробела = «у одного элемента»: `.col-md-9.col-sm-12`
- `:not(.x)` = «без класса x»: отсекает дни соседнего месяца
- кликаем по `label`: там текст, и он видимый (input спрятан)
- `f'{day:03}'`: 5 → `005` (работает с числом, не со строкой)
- `month[:3]`: `'July'` → `'Jul'`
- без `f` перед кавычками `{day}` останется просто текстом

## 7. Именованные аргументы
```python
should_have_registered(email='a@a.ru', full_name='Ivan')
```
Значения раскладываются по **именам**, порядок при вызове неважен.
Порядок задаётся один раз, внутри метода.

## 8. Грабли, на которые я наступил
| Ошибка | Что значит | Что проверить |
|---|---|---|
| `Cannot read properties of null (reading 'remove')` | элемент не найден на странице | `base_url` в `conftest.py`; действие после `browser.open` |
| `Timed out after 2s ... type: Agra` | selene ждал, но элемент недоступен | порядок шагов (город до штата = поле disabled) |
| `NameError: name 'day' is not defined` | такой переменной нет | имя параметра совпадает с тем, что используешь? |
| `takes 1 positional argument but 3 were given` | передали больше аргументов, чем принимает | нужен `*values` |
| `'list' object has no attribute ...` | проверка вызвана на коллекции | забыл `element_by` |

Особенности формы demoqa:
- дата: `.set()` не работает, React возвращает сегодняшнюю дату. Только клики
- календарь: месяц → год → день (клик по дню закрывает календарь)

## 9. Git-привычка
- метод заработал → `git add .` → `git commit -m "..."` → `git push`
- commit = сохранить у себя, push = отправить на GitHub
- `git remote -v` показывает, **куда** уходит push
- `Repository not found` = неверный адрес репозитория, код при этом не потерян
